③ 传输（rsync over SSH — 不是挂载）

为什么不用 rclone / sshfs 挂载
发布是单向动作。挂载把远端伪装成本地磁盘，换来三个代价：断线 hang、删除会取消上传、跨网络逐文件 stat。实测 onedrive 写入 1.5MB/s；far 的 488MB/s 是写缓存假象（删文件时上传被 cancel）。
rsync 三条硬约束
① --chmod=D755,F644：SenseNova 产出的 PNG 是 600，nginx 以 www 用户读不到 → 403
② --delete 只作用于当期目录内部
③ 幂等：重发同一期直接覆盖

边界与失败面

本地是唯一事实源。远端只放成品，任何一期都能从 markdown + PNG 重新生成。远端磁盘满或机器挂掉，不损失原始数据。

与主站的关系

完全独立。opensourceway.blog 主站在 GitHub Pages（185.199.x），这里是自有服务器，两者无耦合。主站挂了不影响这边，反之亦然。
